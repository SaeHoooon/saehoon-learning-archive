Chapter 06 · Deep Feedforward Networks

Section 6.4

Architecture Design

Architecture란?

신경망의 architecture란 크게 layer를 몇 개 사용할 것인지에 해당하는 depth, 각 layer에 unit을 몇 개 둘 것인지에 해당하는 width, 그리고 layer들을 어떻게 연결할 것인지를 결정하는 것을 의미한다.

가장 기본적인 feedforward neural network는 다음과 같은 chain structure를 가진다.

\[ x \rightarrow h^{(1)} \rightarrow h^{(2)} \rightarrow \cdots \rightarrow y \]

첫 번째 hidden layer는

\[ h^{(1)} = g^{(1)} \left( W^{(1)T}x+b^{(1)} \right) \tag{6.40} \]

두 번째 hidden layer는

\[ h^{(2)} = g^{(2)} \left( W^{(2)T}h^{(1)}+b^{(2)} \right) \tag{6.41} \]

로 표현된다. 즉 각 layer에서는 이전 layer의 출력을 받아 affine transformation을 적용하고, 그 결과에 activation function을 적용하는 과정이 반복된다.

예를 들어 \(x\in\mathbb{R}^{100}\rightarrow h^{(1)}\in\mathbb{R}^{50}\rightarrow h^{(2)}\in\mathbb{R}^{20}\rightarrow y\in\mathbb{R}^{10}\) 이라면 hidden layer는 두 개이고, 첫 번째와 두 번째 hidden layer의 width는 각각 50과 20이다.

hidden layer 하나만 있어도 이론적으로 매우 많은 함수를 표현할 수 있지만, 실제로는 깊은 network가 더 적은 unit과 parameter로 같은 함수를 표현할 수 있는 경우가 많다. 다만 network가 깊어질수록 optimization은 어려워질 수 있기 때문에 실제 depth와 width는 validation error를 확인하면서 실험적으로 결정해야 한다.

6.4.1 Universal Approximation Properties and Depth

왜 hidden layer가 필요한가?

Linear model은 다음과 같은 형태를 가진다.

\[ y=W^Tx+b \]

따라서 기본적으로 linear function만 표현할 수 있다. Optimization은 비교적 쉽지만, 현실의 많은 문제는 nonlinear한 관계를 가지므로 nonlinear hidden layer가 필요하다.

Universal Approximation Theorem

Universal Approximation Theorem에 따르면 충분한 수의 hidden unit이 있다면, 적어도 하나의 hidden layer와 적절한 nonlinear activation을 가진 feedforward network는 매우 넓은 종류의 함수를 원하는 정확도까지 근사할 수 있다.

중요한 점은 표현 가능성(representable)과 학습 가능성(learnable)이 같지 않다는 것이다. 원하는 함수를 표현하는 parameter configuration이 network 안에 존재하더라도, 실제 optimization 과정에서 그 parameter를 찾지 못할 수 있고 training data에 overfitting될 수도 있다.

Universal Approximation Theorem은 “신경망이 무엇이든 자동으로 학습한다”는 뜻이 아니라, 충분히 큰 신경망 안에 원하는 함수를 근사하는 parameter configuration이 존재한다는 표현 능력에 관한 정리다.

hidden layer 하나면 충분한데 왜 Deep Learning을 사용하는가?

문제는 하나의 hidden layer만 사용할 경우 필요한 width가 매우 크게 증가할 수 있다는 점이다. 입력이 \(v\in\{0,1\}^n\)인 \(n\)개의 binary variable이라면 가능한 입력 조합은

\[ 2^n \]

개다. 일반적인 binary function을 표현하려면 최악의 경우 \(O(2^n)\) 정도의 자유도가 필요할 수 있기 때문에, shallow network가 지수적으로 커질 수 있다. 따라서 매우 넓은 shallow network보다 depth를 증가시킨 network가 더 효율적인 표현을 제공할 수 있다.

Depth가 주는 표현력

ReLU와 같은 piecewise linear activation을 사용하는 network에서는 입력 공간이 여러 linear region으로 나뉜다. Network가 깊어질수록 앞선 layer가 만든 표현을 다음 layer가 반복적으로 조합하기 때문에 훨씬 많은 linear region을 만들 수 있다.

\[ O\left( \binom{n}{d}^{d(l-1)} n^d \right) \tag{6.42} \]
  • \(d\): input dimension
  • \(l\): network depth
  • \(n\): 각 hidden layer의 unit 수

중요한 것은 식의 세부 상수보다 linear region의 수가 depth \(l\)에 대해 매우 빠르게 증가할 수 있다는 점 이다. 즉 layer가 추가될수록 기존 표현을 다시 조합하면서 더 복잡한 함수를 표현할 수 있다.

Maxout에서도 동일한 현상

각 maxout unit이 \(k\)개의 filter를 가진다면 linear region의 수는 다음과 같은 형태로 증가할 수 있다.

\[ O\left( k^{(l-1)+d} \right) \tag{6.43} \]

이 결과 역시 depth가 증가하면 표현 가능한 영역 수가 매우 빠르게 증가할 수 있다는 점을 보여준다.

Depth의 통계적 의미

Deep architecture를 선택한다는 것은 복잡한 함수가 여러 단순한 함수의 합성으로 이루어져 있을 것이라는 구조적 가정을 모델에 넣는 것과 같다.

\[ f(x) = f^{(L)}\left( f^{(L-1)}\left( \cdots f^{(1)}(x) \right) \right) \]

이미지 인식을 예로 들면 pixel에서 edge, shape, object part, object로 이어지는 것처럼 각 layer가 단순한 transformation을 학습하고 이를 계층적으로 조합한다고 볼 수 있다.

이 결과는 해당 실험에서 depth 증가가 generalization 성능 향상과 함께 나타났음을 보여준다.

즉 deep network의 장점은 단순히 parameter가 많기 때문이라고만 설명할 수 없다. Depth 자체가 “복잡한 함수는 단순한 함수들의 계층적 합성으로 이루어져 있을 것이다” 라는 useful prior를 제공한다.

6.4.2 Other Architectural Considerations

지금까지는 \(h^{(1)}\rightarrow h^{(2)}\rightarrow h^{(3)}\) 처럼 단순한 chain structure를 생각했지만, 실제 neural network에서는 더 다양한 연결 구조를 사용할 수 있다.

Skip Connection

반드시 바로 다음 layer로만 연결될 필요는 없다. 예를 들어 \(h^{(1)}\)에서 \(h^{(3)}\)로 직접 연결되는 것처럼 중간 layer를 건너뛰는 연결을 만들 수 있다. 이를 skip connection이라고 한다.

이러한 연결은 output에서 input에 가까운 layer까지 gradient가 전달되기 쉬운 경로를 제공할 수 있다.

Fully Connected일 필요도 없다

기본적인 fully connected layer에서는 이전 layer의 모든 neuron이 다음 layer의 모든 neuron과 연결된다. 하지만 모든 연결이 항상 필요한 것은 아니다. 일부 연결만 허용하면 parameter 수와 계산량을 줄일 수 있다.

대표적인 예가 CNN의 local connectivity이다. 따라서 좋은 architecture는 단순히 많은 연결을 사용하는 것이 아니라, 문제의 구조에 맞는 connectivity를 사용하는 것 이 중요하다.

Architecture는 어떻게 결정하는가?

6.4에는 backpropagation처럼 별도의 pseudocode 형태의 algorithm이 제시되지는 않는다. Depth, width, connectivity를 선택하고 모델을 학습한 뒤 validation error를 확인하며 architecture를 수정하는 실험적 과정이 중요하다.
